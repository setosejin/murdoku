# murdoku 머도쿠

Murder + Sudoku. 증언을 조합해 범죄현장 평면도 위 인물들의 자리를 확정하고, **피해자와 같은 방에 있던 사람 = 범인**을 지목하는 추리 퍼즐.

```bash
npm install
npm run dev     # 개발 서버
npm test        # 엔진·렌더링 검증
npm run build   # 정적 빌드 (dist/)
```

`main` 에 푸시하면 GitHub Actions 가 빌드해서 GitHub Pages 로 배포한다 (`.github/workflows/deploy.yml`).

## 규칙

1. 모든 인물은 서로 다른 행과 열에 있다 (한 칸에 한 사람).
2. 한 방에 용의자는 한 명까지. 피해자만 그중 한 방에 함께 있다.
3. 가구 위에는 설 수 없다. 침대·러그·건초더미처럼 `standable` 인 것만 예외 — 어느 가구가 예외인지는 사건마다 다르므로 `범례` 가 알려준다.
4. `옆`은 **같은 방 안에서** 상하좌우 인접. 방 경계를 넘지 않는다.
5. 창문·문은 벽 부착물이라 칸을 막지 않고, `~앞`은 그 칸을 뜻한다.
6. 피해자 방에는 용의자가 정확히 1명 — 그 사람이 범인.

방은 직사각형이 아니다. BSP 로 자른 뒤 경계 칸을 이웃 방에 넘겨 L자·T자로 만든다 (연결이 끊기지 않는 이동만 채택).

## 사건 테마

방·가구·사건 제목·직업이 테마 단위로 묶여 있어 `욕실` 과 `돼지우리` 가 한 사건에 섞이지 않는다. 테마는 시드로 정해진다.

| 테마 | 방 | 바닥 |
| --- | --- | --- |
| 저택 | 거실·침실·주방·서재·욕실·손님방·다이닝룸·작업실·복도 | 마루·타일·카펫 |
| 농장 | 마당·목초지·돼지우리·외양간·헛간·창고·정원·작업실·우물가 | 잔디·흙·짚·마루 |

테마를 추가하려면 `src/data/content.ts` 의 `THEMES` 에 하나 더 넣는다. 방 이름은 **9개 이상** 필요하다 (평면도가 최대 9개 방까지 나오고 — 7×7 도 그렇다 — 테스트가 이름 유일성을 검사한다).

## 화면

셸이 둘이다. `useMediaQuery(MOBILE_QUERY)` 가 고르고, 게임 상태(`useGame`)와 패널 컴포넌트는 둘이 함께 쓴다 — 그래서 창 크기를 바꿔도 사건과 메모가 그대로 남는다.

**둘 다 한 화면에 들어간다.** 데스크톱은 세 열로 편다.

```
 murdoku   [저택] 사라진 회중시계 브리핑⌄   (4×4 5×5 6×6 7×7) [새 사건] [⋯]
┌──────────────┬───────────────────┬──────────────┐
│ 증언          │                   │ 범인은?       │
│ Ⓐ 민준 …      │       보드         │ Ⓐ Ⓑ Ⓒ       │
│ Ⓑ 서연 …      │                   │ [지목하기]    │
│ [✕ 빈칸][지우기]│                   │ 범례          │
└──────────────┴───────────────────┴──────────────┘
```

증언을 읽는 자리가 곧 브러시를 고르는 자리다 — 줄을 누르면 그 인물로 칸을 표시한다(모바일이 먼저 쓴 방식). 사건 브리핑·규칙은 제목 버튼이, 시드·기록·계정·피드백은 `⋯` 가 여는 모달에 들어간다. 넘치는 몫은 페이지가 아니라 열 안에서 스크롤한다.

**모바일(좁거나 낮은 화면)은 스크롤이 없다.** 한 화면에 셋만 붙박이로 둔다.

```
┌──────────────────────────────────────┐
│ [저택] 사라진 회중시계  ⌄       [☰] │  ← 제목 탭 = 사건 시트 / ☰ = 메뉴 시트
├──────────────────────────────────────┤
│              보드                     │  ← 폭·높이 중 작은 쪽에 맞춘 정사각
├──────────────────────────────────────┤
│ Ⓐ 민준  난 침대 옆에 있었어!         │  ← 증언 목록이 곧 메모 브러시.
│ Ⓥ 지우  마지막 남은 자리에 있어…     │     줄을 누르면 그 인물로 칸을 표시한다
├──────────────────────────────────────┤
│ [✕ 빈칸]    [범례]    [지목하기]     │
└──────────────────────────────────────┘
```

나머지(사건 설명·규칙·범례·지목·난이도·시드·기록·계정)는 전부 바텀시트에 들어간다. 스크롤은 시트 안에서만 생긴다.

보드는 `min(100cqw, 100cqh)` 로 남는 공간의 짧은 변에 맞춘다(`@supports not (container-type: size)` 폴백은 예전처럼 폭만 본다). 칸 안의 글자·아이콘도 뷰포트가 아니라 **보드 폭**(`cqw`)을 따라가야 보드가 줄었을 때 같이 준다.

> `src/hooks/useMediaQuery.ts` 의 `MOBILE_QUERY` 와 `src/styles/mobile.css` 의 미디어 쿼리는 **글자까지 같아야 한다**. 어긋나면 마크업은 모바일인데 스타일은 데스크톱이 된다. 테스트가 일치를 검사한다.

## 플레이 기록

해결한 사건이 `기록` 패널에 쌓이고(모바일은 `☰` 메뉴 시트 안), 항목을 누르면 그 사건이 다시 열린다. 같은 자리의 `점수판` 이 총점과 TOP 10 을 보여준다.

**퍼즐은 저장하지 않는다.** `generatePuzzle(n, seed)` 가 결정적이라 `seed` + `n` 이면 사건이 통째로 복원되기 때문이다. 기록 한 건은 이 정도다:

```ts
type Play = { seed; n; at; ok; tries; title };  // 약 80바이트
```

`title` 만 중복 저장하는데, 목록을 그릴 때마다 생성기를 돌리면 어려움 난이도가 건당 100ms 라서다.

### 기기 간 동기화

`VITE_SYNC_URL` 이 설정된 빌드에서만 켜진다. **없으면 기록은 그 기기 안에서만 남고, 게임은 똑같이 돌아간다.**

- 저장 계층의 신원은 **기록 코드** — 앱이 만든 22자 랜덤 문자열이다. 다른 기기에 입력하면 기록이 따라온다. 시드 박스와 같은 방식. 아래 [계정](#계정-아이디비밀번호)은 이 코드를 꺼내오는 층일 뿐이다.
- **localStorage 가 주 저장소고 서버는 동기화 계층이다.** 네트워크가 죽어도 기록은 남고, 정답을 맞춘 순간 화면이 멈추지 않는다.
- 기록은 append-only 라 **병합이 그냥 합집합**이다. 충돌 해소 로직이 없다.
- 검증(`sanitizePlays`)은 클라이언트와 워커가 **같은 함수**를 쓴다. `matchingCells` 와 같은 이유로 복제하지 않는다.

한계는 알고 쓰는 게 낫다:

- **코드를 아는 사람은 그 기록을 보고 바꿀 수 있다.** 담기는 건 시드·승패·시각뿐이라 감수한 선택이다.
- **엔드포인트는 인증이 없다.** 주소는 번들에 박혀 공개되고, CORS 는 브라우저 정책이라 스크립트는 막지 못한다. 방어선은 두 가지다 — 22자 랜덤 코드는 추측할 수 없고(36²²), **워커는 병합 결과가 비었거나 저장본과 같으면 KV 에 쓰지 않는다.** 덕분에 아무 코드나 찍어 보내는 요청은 쓰기 한도(1천/일)를 먹지 않는다. 그래도 부족하면 Cloudflare 대시보드의 레이트 리밋 규칙을 건다(코드 수정 없음).
- KV 는 최종 일관성이라, 한 기기에서 풀고 곧바로 다른 기기를 열면 최대 1분쯤 늦게 보일 수 있다.
- `기록 지우기` 는 이 기기의 기록을 비우고 코드를 새로 뽑는다. 서버 사본은 남지만 코드를 잃어 도달할 수 없다.

### 점수와 순위표

점수는 **저장 구조를 안 건드린다.** `Play` 에 이미 있는 `n`(난이도)·`tries`(지목 횟수)·`ok` 만으로 계산되는 순수 함수라, 클라이언트도 워커도 같은 `scoreOf` 를 부른다 — `matchingCells` 와 같은 이유로 판정을 복제하지 않는다.

```
만점 = 난이도(4×4 150 · 5×5 250 · 6×6 350 · 7×7 450)
점수 = max(만점 - (지목 횟수 - 1) × 만점/5, 만점/5)
```

한 번에 맞히면 만점, 지목이 늘 때마다 20%씩 깎이고 20%는 남는다. 격자가 정사각이라 한 변(`n`)이 곧 키다 — 가로세로 다른 격자가 생기면 그 몫으로 500 을 둔다.

점수를 불리는 길 둘을 막아뒀다.

- **정답을 보면 그 사건은 거기서 끝난다.** `정답 보기` 는 누르기 전에 대가를 말하고(`정답 보기 (이 사건 포기)`), 누른 뒤에는 `지목하기` 가 잠긴다. 기록에도 점수에도 남지 않는다. 잠금은 `revealed` 가 아니라 따로 둔 `peeked` 로 건다 — `revealed` 는 토글이라 다시 감추면 흔적이 사라진다.
- **같은 사건은 첫 해결만 친다.** 기록에서 사건을 다시 열어 답을 알고 한 번에 맞혀도 총점은 안 오른다 (`summarize` 가 `seed:n` 마다 가장 이른 `at` 을 고른다).

`Play.ok` 는 이제 앱이 `false` 로 쓰는 길이 없지만 검증은 남겨둔다 — `sanitizePlays` 가 받는 값은 네트워크와 localStorage 에서 오고, `scoreOf` 는 그런 기록을 0점으로 친다.

순위표는 **계정만 오른다.** 줄을 세우려면 이름이 필요하고, 그 이름은 가입 때 서버가 못박은 아이디다. 게스트는 이름이 없으니 순위 없이 점수만 본다.

| 라우트 | 요청 | 응답 |
|---|---|---|
| `POST /lb/:code` | 없음 | `{top: Rank[], rank: number\|null}` |

- **점수는 서버가 센다.** 클라이언트가 올린 숫자를 받는 게 아니라, KV 에 저장된 `Play[]` 에서 `summarize` 로 계산한다. 기록 자체는 여전히 위조 가능하지만(엔드포인트에 인증이 없다) 점수 필드를 지어내는 길은 없다.
- `내 점수` 는 로컬 기록에서 바로 센다 — 서버 왕복 없이 항상 최신이고, `VITE_SYNC_URL` 이 없는 빌드에서도 보인다. 서버가 주는 건 남들의 줄과 내 순위뿐이다.
- 순위 전체가 KV 한 키(`lb`)에 들어가고 갱신은 통째로 다시 쓴다. **CAS 가 없어 동시에 올리면 한쪽이 덮이지만** 다음 해결 때 제 점수로 다시 오른다. 실시간 정확도가 필요해지면 Durable Objects.
- 순위 갱신은 **기록이 안 바뀐 요청에서도** 일어난다. 바뀐 요청에만 맡기면 순위표가 생기기 전에 다 풀어둔 사람은 새 사건을 풀기 전까지 영영 순위 밖이다. 대신 쓰기는 `updateBoard` 가 스스로 막는다 — 점수와 사건 수가 그대로면 처음 오른 시각(`at`)까지 그대로 두어 직렬화 결과가 같아지고, 같으면 KV 에 안 쓴다. `at` 을 매번 새로 찍으면 아무것도 안 바뀐 요청마다 쓰기가 나간다.
- 코드 → 표시 이름은 `c:<코드>` 매핑이다. 가입 때 쓰고, 그전에 만든 계정은 로그인할 때 한 번 메운다.
- `MAX_BOARD`(100)명까지만 들고 있다. 밖으로 밀려나면 순위를 잃는다 — 이 규모에서 필요해지면 그때 올린다.

### 계정 (아이디/비밀번호)

코드를 옮겨적기 번거로워서 로그인을 얹었다. **로그인은 선택이다** — 안 해도 게임과 로컬 기록은 지금 그대로 돌아간다.

핵심은 **계정을 기록 저장 구조에 끼워넣지 않은 것**이다. 기록 코드가 이미 신원 역할을 하니까(KV 키가 곧 코드다), 계정은 `(아이디, 비밀번호) → 코드` 조회 층일 뿐이다.

```
로그인 성공 → setCode(계정 코드) → 기존 useEffect([code]) 발화
            → sync(계정 코드, loadPlays()) → 서버 기록과 이 기기 기록을 합침
```

덕분에 `sync()`·`mergePlays`·`sanitizePlays`·`POST /h/:code` 가 **한 줄도 안 바뀌었다.** 익명으로 풀던 기록이 가입하는 순간 계정으로 합쳐지는 것도 이관 코드 없이 저절로 된다.

**비밀번호는 브라우저에서 늘린다.**

```
클라이언트: dk = hex( PBKDF2-SHA256(pw, "murdoku:"+id, 310_000회, 32B) )
서버 가입 : s = 랜덤 16B;  KV["u:"+id] = { s, h: SHA-256(s+dk), code }
서버 로그인: 상수시간 비교( SHA-256(s+dk), h )
```

서버가 아니라 클라이언트에서 돌리는 이유가 셋이다.

1. **Workers 무료 티어는 요청당 CPU 10ms** 다. 서버에서 31만 회를 돌리면 한도를 넘긴다.
2. 서버가 비밀번호 원문을 아예 못 본다.
3. 무차별 대입이 공격자 CPU 를 한 번에 31만 회씩 먹는다.

31만은 [OWASP 권고치](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)고, 실측으로 감당되는 걸 확인하고 골랐다(개발 기기 64ms, 가입 왕복 전체 110ms). WebCrypto 는 브라우저·workerd 양쪽 기본 제공이라 **의존성이 늘지 않았다.**

| 라우트 | 요청 | 응답 |
|---|---|---|
| `POST /a/signup` | `{id, dk}` | 201 `{code}` · 409 아이디 중복 · 400 형식 |
| `POST /a/login` | `{id, dk}` | 200 `{code}` · 401 불일치 · 400 형식 |

**코드는 반드시 서버가 만든다.** 클라이언트가 고를 수 있으면 남의 코드를 자기 계정에 등록해 기록을 가져갈 수 있다. 테스트가 이걸 지킨다.

KV 키 공간은 겹치지 않는다 — 기록은 `^[a-z0-9]{22}$`, 계정은 `u:<아이디>`, 이름 매핑은 `c:<코드>`, 순위표는 `lb`. 콜론이 있어 `POST /h/u:sejin` 은 400 이다.

알고 쓸 것:

- **비밀번호 재설정이 없다.** 이메일을 안 받으니 서버가 해줄 수 있는 게 없다. 그래서 **기록 코드를 "복구 키"로 남겨뒀다** — 적어둔 사람은 비밀번호를 잊어도 기록을 되찾는다.
- **로그아웃은 이 기기를 게스트로 되돌린다.** 로컬 기록을 비우고 새 익명 코드를 뽑는다. 공유 기기에 기록이 남지 않게. 서버에 계정 사본이 있으니 다시 로그인하면 그대로 돌아온다.
- **가입은 KV 쓰기 1회**라 무한 가입이 하루 1천 쓰기 한도를 태울 수 있다. 로그인은 쓰기 0회다. 필요해지면 Cloudflare 대시보드에서 `/a/*` 에 레이트 리밋 규칙을 건다(코드 수정 없음).
- KV 에 CAS 가 없어 **같은 아이디 동시 가입이 이론상 경합**한다. 이 규모에서 감수한다. 막아야 하면 Durable Objects 로 올린다.
- 가입 직후 다른 기기에서 로그인하면 KV 최종 일관성 탓에 잠깐 실패할 수 있다.
- `VITE_SYNC_URL` 이 없는 빌드(포크 등)에서는 로그인 UI 를 아예 안 그린다.

### 관리 화면

`admin.html` — 게임과 **다른 URL, 다른 번들**이다. 라우터를 얹는 대신 Vite 의 다중 진입점을 쓴다(`vite.config.ts` 의 `rollupOptions.input`). 관리 화면 코드는 게임 번들에 안 실리고, 그 반대도 마찬가지다.

```
https://<사이트>/admin.html
```

**정적 호스팅에는 접근 제어가 없다.** GitHub Pages 는 이 HTML 을 누구에게나 준다 — 페이지를 숨겨서 막을 방법은 없고, 숨긴 URL 은 보안이 아니다. 그래서 **문지기는 페이지가 아니라 워커**다. `/adm/*` 는 전부 `x-admin-token` 헤더를 요구하고 상수시간으로 비교한다. 토큰이 없으면 목록조차 안 온다 — 화면이 비어 있는 게 아니라 데이터가 오지 않는 것이다.

```bash
cd worker
npx wrangler secret put ADMIN_TOKEN     # openssl rand -hex 32
```

**시크릿을 안 넣으면 전부 401 이다.** "설정 안 했으니 통과"가 아니라 "설정 안 했으니 전원 차단"이고, 테스트가 그 방향을 고정한다.

할 수 있는 것:

| | |
| --- | --- |
| `POST /adm/list` | 계정 목록 + 기록 코드 목록. **키 이름만 읽는다** — 값을 안 열어서 계정이 늘어도 KV 조회 수가 그대로다 |
| `POST /adm/get` | `{id}` 나 `{code}` 로 기록·점수·사건 수. 점수는 순위표와 같은 `summarize` 를 쓴다 |
| `POST /adm/del` | `{code}` 면 기록만, `{id}` 면 계정까지. 어느 쪽이든 순위표에서도 내려간다 |

알고 쓸 것:

- 토큰은 `sessionStorage` 에만 둔다. 탭을 닫으면 사라지고, 401 을 받으면 화면이 스스로 잠긴다.
- **요청 제한은 없다.** 32바이트 난수를 네트워크로 맞히는 건 현실적으로 불가능해서 감수한 선택이다. 관리자가 여럿이 되거나 감사 기록이 필요해지면 앞에 Cloudflare Access 를 세운다.
- 게스트 기록은 `c:<코드>` 매핑이 없는 코드로 알아본다. 주인을 알 방법은 없다 — 코드가 곧 신원이라서다.
- 검색·필터는 없다. 목록이 길어지면 그때 붙인다.

### 워커 배포

KV 네임스페이스는 이미 만들어 `wrangler.toml` 에 박아뒀다. 배포만 하면 된다:

```bash
cd worker
npx wrangler deploy
```

처음이라면 Cloudflare 계정의 **이메일 인증이 끝나 있어야 한다.** 안 되어 있으면 업로드까지 다 하고 마지막에 `code: 10034` 로 떨어진다.

배포되면 주소는 `https://murdoku-history.murdoku.workers.dev` 다. 이걸 저장소 Settings → Secrets and variables → Actions → **Variables** 에 `VITE_SYNC_URL` 로 넣으면 다음 Pages 배포부터 동기화가 켜진다.

**시크릿이 아니라 variable 인 이유**: 정적 사이트라 이 주소는 어떻게 저장하든 빌드된 JS 에 그대로 박힌다. 시크릿으로 바꿔도 devtools 를 열면 보이니 숨기는 효과가 0 이다. 그래도 소스에 하드코딩하지 않는 이유는 보안이 아니라 두 가지다 — **포크한 저장소가 원본 워커로 요청을 보내지 않고**(variable 이 비어 로컬 전용으로 동작), 주소를 바꿀 때 코드를 안 고쳐도 된다.

워커는 거의 안 바뀌므로 CI 없이 손으로 배포한다. 자주 고치게 되면 그때 워크플로를 붙인다.

**Pages 는 자동, 워커는 수동이다.** 라우트가 늘어나는 변경(순위표·관리 화면처럼)을 배포하면서 `wrangler deploy` 를 잊으면, 새 화면은 떴는데 서버에는 그 라우트가 없어 조용히 실패한다. 실제로 순위표가 이렇게 빈 채로 나갔다. 워커를 고쳤으면 배포한 뒤 라우트가 살아 있는지 확인할 것:

```bash
curl -s -X POST https://murdoku-history.murdoku.workers.dev/lb/$(printf 'a%.0s' {1..22})
# {"top":[...],"rank":null} 이면 정상. "기록 코드가 아니다" 면 옛 워커가 그대로 떠 있는 것이다
```

## 그림 에셋 붙이기

아이콘은 `image` → `sprite.svg` → 이모지 순으로 떨어진다.

- 스프라이트에 `id="i-<kind>"` 로 `<symbol>` 을 넣으면 그 가구가 자동으로 그 아이콘을 쓴다. 선 색·굵기는 CSS 의 `svg.art` 가 한 번에 정하므로 심볼에는 모양과 색만 넣는다.
- `Person` · `Furniture` · `WallItem` 의 `image?` 필드에 경로를 넣으면 그 이미지를 우선 그린다.
- 둘 다 없으면 이모지로 떨어지므로, 아이콘 없는 가구를 추가해도 깨지지 않는다.

## 링크 미리보기 (카카오톡·트위터)

`index.html` 의 `<head>` 에 Open Graph 태그가 정적으로 박혀 있고, 카드 이미지는 `public/og.png` 다.

지켜야 하는 것 넷 — 하나만 어긋나도 **빈 링크로 전달되는데 배포 전에는 티가 안 난다.** `repo.test.ts` 의 `링크 미리보기` 가 넷 다 검사한다.

- **정적 HTML 이어야 한다.** 카카오 스크래퍼는 JS 를 실행하지 않는다. 런타임에 `document.head` 로 심으면 안 읽힌다.
- **`og:image` 는 절대 URL.** `base: './'` 라고 favicon 처럼 상대 경로로 "정리"하면 스크래퍼가 해석하지 못해 이미지가 통째로 빠진다.
- **PNG 나 JPG.** 카카오는 SVG 를 안 읽는다 — favicon 이 SVG 라고 따라가면 안 된다.
- **2:1.** 카카오가 미리보기를 2:1 로 스마트 크롭한다. `og.png` 는 1200×600 이다.

이미지를 바꾸면 `?v=` 를 올리고 [카카오 디버거](https://developers.kakao.com/tool/debugger/sharing)에서 캐시를 지운다. 카카오는 스크랩 결과를 몇 시간 캐싱해서, 그냥 두면 옛 이미지가 계속 나간다.

`og.png` 는 **앱 화면에서 떠온 진짜 보드**다. 손으로 그린 그림이 아니라서 UI 가 바뀌면 낡는다. 다시 만드는 법 — `npm run dev` 로 띄우고, 정답을 공개해 인물이 놓인 보드(`.board`)를 통째로 복제한 뒤 제목 옆에 붙여 1200×600 으로 찍는다. 이때 가구 그림이 참조하는 숨은 `<svg>` 스프라이트를 같이 복제해야 한다 — `<use href="#i-*">` 만 옮기면 가구가 전부 빈칸으로 나온다.

## 버전 기록

푸터의 버전 번호를 누르면 [`CHANGELOG.md`](CHANGELOG.md) 가 모달로 열린다.

릴리스는 이 순서로만 한다. `main` 푸시는 버전을 올려야 통과한다 — `.githooks/pre-push` 가 `origin/main` 대비 버전과 `CHANGELOG.md` 항목을 확인하고, 훅을 넘겨도 CI 의 `npm test` 가 같은 걸 본다. 훅은 `npm install` 이 알아서 걸어준다.

```bash
# 1. CHANGELOG.md 맨 위에 "## v<새 버전> — <YYYY-MM-DD>" 를 쓰고 변경 내용과 함께 커밋
npm version patch      # 또는 minor / major
git push --follow-tags
```
