# murdoku 머도쿠

Murder + Sudoku. 증언을 조합해 범죄현장 평면도 위 인물들의 자리를 확정하고, **피해자와 같은 방에 있던 사람 = 범인**을 지목하는 추리 퍼즐.

```bash
npm install
npm run dev     # 개발 서버
npm test        # 엔진·렌더링 검증
npm run build   # 정적 빌드 (dist/)
```

`main` 에 푸시하면 GitHub Actions 가 빌드해서 GitHub Pages 로 배포한다 (`.github/workflows/deploy.yml`).

## 규칙

1. 모든 인물은 서로 다른 행과 열에 있다 (한 칸에 한 사람).
2. 한 방에 용의자는 한 명까지. 피해자만 그중 한 방에 함께 있다.
3. 가구 위에는 설 수 없다. 침대·러그·건초더미처럼 `standable` 인 것만 예외 — 어느 가구가 예외인지는 사건마다 다르므로 사이드의 `범례` 패널이 알려준다.
4. `옆`은 **같은 방 안에서** 상하좌우 인접. 방 경계를 넘지 않는다.
5. 창문·문은 벽 부착물이라 칸을 막지 않고, `~앞`은 그 칸을 뜻한다.
6. 피해자 방에는 용의자가 정확히 1명 — 그 사람이 범인.

방은 직사각형이 아니다. BSP 로 자른 뒤 경계 칸을 이웃 방에 넘겨 L자·T자로 만든다 (연결이 끊기지 않는 이동만 채택).

## 사건 테마

방·가구·사건 제목·직업이 테마 단위로 묶여 있어 `욕실` 과 `돼지우리` 가 한 사건에 섞이지 않는다. 테마는 시드로 정해진다.

| 테마 | 방 | 바닥 |
| --- | --- | --- |
| 저택 | 거실·침실·주방·서재·욕실·손님방·다이닝룸·작업실·복도 | 마루·타일·카펫 |
| 농장 | 마당·목초지·돼지우리·외양간·헛간·창고·정원·작업실·우물가 | 잔디·흙·짚·마루 |

테마를 추가하려면 `src/data/content.ts` 의 `THEMES` 에 하나 더 넣는다. 방 이름은 **9개 이상** 필요하다 (6×6 평면도가 최대 9개 방까지 나오고, 테스트가 이름 유일성을 검사한다).

## 구조

| 파일                         | 역할                                                             |
| ---------------------------- | ---------------------------------------------------------------- |
| `src/game/types.ts`        | 데이터 모델, 시드 RNG                                            |
| `src/game/clues.ts`        | 증언 판정(`matchingCells`)과 한국어 문구 — 규칙의 유일한 출처 |
| `src/game/solve.ts`        | 행/열/방 비트마스크 백트래킹 솔버 + 유일해 판정                  |
| `src/game/generate.ts`     | BSP 평면도 → 가구 → 정답 배치 → 증언 → 유일해 검증 루프      |
| `src/data/content.ts`      | `THEMES` — 테마별 방·바닥·가구·제목·직업 풀                  |
| `src/components/Board.tsx` | 격자·방 경계·바닥 재질·가구·메모 렌더                         |
| `src/assets/sprite.svg`    | 가구·벽부착물·인물 아이콘 (`<symbol id="i-<kind>">`)          |
| `src/game/history.ts`      | 플레이 기록 — 검증·병합(순수) + localStorage + 동기화          |
| `worker/index.ts`          | 기록 동기화 워커 (Cloudflare Workers + KV)                       |
| `src/components/FeedbackDialog.tsx` | 피드백 모달 → GitHub 이슈 작성 폼 prefill                |

증언은 `ON` / `NEXT_TO` / `IN_ROOM` 세 종류. 퍼즐은 매번 생성되며 항상 해가 하나뿐임이 보장된다.

## 플레이 기록

해결한 사건이 우측 `기록` 패널에 쌓이고, 항목을 누르면 그 사건이 다시 열린다.

**퍼즐은 저장하지 않는다.** `generatePuzzle(n, seed)` 가 결정적이라 `seed` + `n` 이면 사건이 통째로 복원되기 때문이다. 기록 한 건은 이 정도다:

```ts
type Play = { seed; n; at; ok; tries; title };  // 약 80바이트
```

`title` 만 중복 저장하는데, 목록을 그릴 때마다 생성기를 돌리면 어려움 난이도가 건당 100ms 라서다.

### 기기 간 동기화

`VITE_SYNC_URL` 이 설정된 빌드에서만 켜진다. **없으면 기록은 그 기기 안에서만 남고, 게임은 똑같이 돌아간다.**

- 신원은 로그인이 아니라 **기록 코드** — 앱이 만든 22자 랜덤 문자열이다. 다른 기기에 입력하면 기록이 따라온다. 시드 박스와 같은 방식.
- **localStorage 가 주 저장소고 서버는 동기화 계층이다.** 네트워크가 죽어도 기록은 남고, 정답을 맞춘 순간 화면이 멈추지 않는다.
- 기록은 append-only 라 **병합이 그냥 합집합**이다. 충돌 해소 로직이 없다.
- 검증(`sanitizePlays`)은 클라이언트와 워커가 **같은 함수**를 쓴다. `matchingCells` 와 같은 이유로 복제하지 않는다.

한계는 알고 쓰는 게 낫다:

- **코드를 아는 사람은 그 기록을 보고 바꿀 수 있다.** 담기는 건 시드·승패·시각뿐이라 감수한 선택이다. 진짜 계정이 필요해지면 그때 로그인을 얹는다.
- **엔드포인트는 인증이 없다.** 주소는 번들에 박혀 공개되고, CORS 는 브라우저 정책이라 스크립트는 막지 못한다. 방어선은 두 가지다 — 22자 랜덤 코드는 추측할 수 없고(36²²), **워커는 병합 결과가 비었거나 저장본과 같으면 KV 에 쓰지 않는다.** 덕분에 아무 코드나 찍어 보내는 요청은 쓰기 한도(1천/일)를 먹지 않는다. 그래도 부족하면 Cloudflare 대시보드의 레이트 리밋 규칙을 건다(코드 수정 없음).
- KV 는 최종 일관성이라, 한 기기에서 풀고 곧바로 다른 기기를 열면 최대 1분쯤 늦게 보일 수 있다.
- `기록 지우기` 는 이 기기의 기록을 비우고 코드를 새로 뽑는다. 서버 사본은 남지만 코드를 잃어 도달할 수 없다.

### 워커 배포

```bash
cd worker
npx wrangler kv namespace create HISTORY   # 출력된 id 를 wrangler.toml 에 붙인다
npx wrangler deploy
```

배포된 주소를 저장소 Settings → Secrets and variables → Actions → **Variables** 에 `VITE_SYNC_URL` 로 넣으면 다음 배포부터 동기화가 켜진다.

**시크릿이 아니라 variable 인 이유**: 정적 사이트라 이 주소는 어떻게 저장하든 빌드된 JS 에 그대로 박힌다. 시크릿으로 바꿔도 devtools 를 열면 보이니 숨기는 효과가 0 이다. 그래도 소스에 하드코딩하지 않는 이유는 보안이 아니라 두 가지다 — **포크한 저장소가 원본 워커로 요청을 보내지 않고**(variable 이 비어 로컬 전용으로 동작), 주소를 바꿀 때 코드를 안 고쳐도 된다.

워커는 거의 안 바뀌므로 CI 없이 손으로 배포한다. 자주 고치게 되면 그때 워크플로를 붙인다.

## 그림 에셋 붙이기

아이콘은 `image` → `sprite.svg` → 이모지 순으로 떨어진다.

- 스프라이트에 `id="i-<kind>"` 로 `<symbol>` 을 넣으면 그 가구가 자동으로 그 아이콘을 쓴다. 선 색·굵기는 CSS 의 `svg.art` 가 한 번에 정하므로 심볼에는 모양과 색만 넣는다.
- `Person` · `Furniture` · `WallItem` 의 `image?` 필드에 경로를 넣으면 그 이미지를 우선 그린다.
- 둘 다 없으면 이모지로 떨어지므로, 아이콘 없는 가구를 추가해도 깨지지 않는다.

## 아직 없는 것

- 거짓말하는 용의자 / 목격자 / 알리바이 같은 트릭 (증언 타입 하나 추가로 확장 가능)
- 7×7 이상 대형 격자 — 솔버가 완전 백트래킹이라 그때 제약 전파 필요
- 계정·랭킹. 퍼즐은 전부 클라이언트에서 돌고, 서버가 하는 일은 기록 JSON 을 넣고 빼는 것뿐이다.
- 피드백 자동 등록. 정적 배포라 토큰을 둘 곳이 없어서, 모달 입력값으로 GitHub 이슈 작성 폼을 채워 열어주고 등록은 GitHub 에서 사용자가 누른다.
