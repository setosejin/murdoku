# 플레이 도중에 알려주기 — 피해자가 누구인지, 무엇을 맞히는 게임인지

## 문제

플레이한 사람이 말했다.

> 튜토리얼 대충 읽었는데 모르고 읽다보니 숙지가 덜되는 부분이 있어서 V가 죽은사람인지,
> 같은 공간에 있는 사람이 범인인지 룰 다시보고 알았습니다

막힌 지점은 둘이다.

1. **`V` 뱃지가 죽은 사람이라는 걸 몰랐다.** 용의자 중 하나인 줄 알았다.
2. **승리 조건을 몰랐다** — 피해자와 같은 방에 있던 용의자가 범인.

둘 다 앱에 이미 적혀 있다. **정보가 없는 게 아니라 필요한 순간에 그 자리에 없다.**

| 사실 | 지금 어디 있나 | 왜 못 만나나 |
|---|---|---|
| V = 피해자 | `CaseCards` 의 `<small>{role} · 피해자</small>` + 초상 위 빨간 X | 사건 브리핑 모달/시트 **안** |
| 승리 조건 | `RulesPanel` 8번 + 온보딩 3단계 | 둘 다 모달 **안** |

플레이어가 실제로 오래 보는 자리 — 증언 목록과 보드와 지목 패널 — 에는 둘 다 없다.

### V 행이 용의자 행과 구별되지 않는다

`ClueList` 는 피해자를 용의자와 **똑같이** 그린다. 같은 `.clue-row`, 같은 `.clue-badge`,
다른 건 문구뿐이다.

```tsx
<span className="clue-badge" style={{ background: p.color }}>{p.id}</span>
<b>{p.name}</b>
<span className="clue-text">{p.isVictim ? VICTIM_LINE : clueOf(p.id)}</span>
```

`VICTIM_LINE` 은 `'마지막 남은 자리에 있어…'` 다. **피해자가 말하는 투**라
오히려 "살아서 진술하는 용의자"로 읽힌다. 죽었다는 신호가 어디에도 없다.

### 모바일에는 온보딩이 아예 없다

`Tour` 는 데스크톱 셸 전용이다(`Tour.tsx` 주석이 이유를 적어뒀다 — 겨누는 자리인
`.dclues`·`.legend` 가 모바일 메인 화면에 없다). 다시 여는 `?` 버튼도 데스크톱만 받는다
(`BrushBar` 의 `onHelp` 는 `App.tsx` 만 넘긴다).

**모바일 사용자는 튜토리얼을 건너뛴 게 아니라 본 적이 없다.** 규칙 전문에 닿으려면
상단바의 사건 제목을 눌러야 한다는 걸 스스로 알아내야 한다.

## 접근

**화면에 자리를 더 내지 않는다.** 모바일은 스크롤이 없고 데스크톱도 `100dvh` 한 화면이다.
패널을 하나 더 붙이면 그만큼 보드가 작아진다. 그래서 세 가지 다 **이미 있는 것 위에**
얹는다.

1. **빨간 X 를 피해자 전용 기호로 세 곳에 심는다** — 증언 줄 뱃지 · 지목 패널 문장 ·
   보드의 **정답 공개 토큰**. 브리핑 카드가 이미 쓰는 기호라 새 언어를 만드는 게 아니라
   **원래 있던 언어를 넓히는** 것이다.
2. **승리 조건을 지목하는 자리에 상시로 둔다** — 규칙이 필요한 순간은 지목할 때다.
3. **모바일 첫 방문에 사건 시트를 저절로 연다** — 시트 안에 브리핑·카드·범례·규칙이
   이미 다 있다. 문구 복제가 0이다.

게임 로직(`src/game/*`)은 손대지 않는다. 규칙은 원래 맞게 돌아가고 있었고 말과 그림이
못 따라가고 있었을 뿐이다. **같은 시드는 같은 답을 유지한다.**

### 따져보고 버린 대안

- **규칙 패널에 문장을 더 넣기** — 지적한 사람은 모달을 안 열어서 막혔다. 같은 모달 안에
  글을 더 넣는 건 같은 문을 한 번 더 잠그는 것이다.
- **메인 화면에 규칙 요약 패널** — 모바일 붙박이가 넷에서 다섯이 되고 그만큼 보드가 줄어든다.
  늘 필요하지 않은 것은 시트로 내리는 게 이 저장소의 방식이다.
- **`지목하기` 에 확인 단계** — 가장 확실히 읽히지만 매 판 한 번씩 더 누르게 된다.
  상시 한 줄이 같은 일을 공짜로 한다.
- **정답 순간에 규칙 캡션** — 지목 패널 맨 위에 그 문장이 이미 상시로 있어 중복이고,
  `.notice` 자리는 거절 토스트가 이미 쓴다.
- **모바일 스포트라이트 온보딩 포팅** — 단계마다 시트를 여닫는 오케스트레이션이 필요하다.
  이번 피드백 범위보다 훨씬 크고, 사건 시트가 같은 내용을 이미 갖고 있다.

## 1. 빨간 X = 피해자

### 단일 출처

X 그림은 `base.css` 의 `:root` 에 **한 번만** 둔다. 값이 두 벌이면 언젠가 갈라진다.

```css
--dead-x: linear-gradient(to bottom right, #0000 calc(50% - 4%), var(--accent) calc(50% - 4%) calc(50% + 4%), #0000 calc(50% + 4%)),
          linear-gradient(to bottom left,  #0000 calc(50% - 4%), var(--accent) calc(50% - 4%) calc(50% + 4%), #0000 calc(50% + 4%));
```

굵기를 px 이 아니라 **퍼센트**로 잡는다. 24px 뱃지와 보드 토큰(격자 크기에 따라 20~40px)이
같은 비율로 보여야 한다. 두 carrier 모두 정사각이라 축마다 왜곡되지 않는다.

위 `4%` 는 출발값이다. 뱃지와 토큰을 나란히 놓고 브라우저에서 확정한다 — 판정 기준은
**24px 뱃지에서 `V` 가 읽히면서 X 의 네 끝이 글자 밖으로 삐져나오는가**다. 획이 너무 굵으면
글자를 먹고, 너무 가늘면 작은 뱃지에서 사라진다.

브리핑 카드의 초상 X(`.card.victim .portrait::after`)는 **그대로 둔다.** 4:3 이라 퍼센트가
축마다 달라지고, 지금 px 값으로 이미 잘 보인다.

`calc()` 안에 `var()` 를 넣지 않는다 — 값이 바뀌는 자리에서 WebKit 이 캐싱한다(webkit#202259).
여기 `calc()` 는 리터럴만 들었고 `var(--accent)` 는 색 치환이라 해당하지 않는다.

### 글자를 가리지 않게 깐다

뱃지와 토큰 둘 다 가운데에 글자(`V`)가 있다. X 가 위에 오면 글자를 먹는다.

`::before` 를 `position: absolute; z-index: -1` 로 둔다. 음수 z-index 자식은 **자기 부모의
배경 위, 인라인 내용 아래**에 그려진다 — 회색 뱃지 위에 빨간 X, 그 위에 잉크색 `V` 다.

- `.clue-badge` 는 스태킹 컨텍스트가 없으므로 `position: relative; isolation: isolate` 를 준다.
  **`isolation` 없이 `z-index: -1` 을 쓰면 X 가 `.clue-row` 배경 뒤로 빠져 아예 안 보인다.**
- `.token` 은 이미 `position: relative; z-index: 2` 라 스태킹 컨텍스트가 있다. 그대로 먹는다.

### 심는 곳 셋

| 자리 | 마크업 | 비고 |
|---|---|---|
| 증언 목록 (`ClueList`) | `.clue-badge dead` | 두 셸 공용 |
| 지목 패널 문장 (`AccusePanel`) | `.clue-badge dead`, `aria-hidden` | 두 셸 공용 |
| 보드 토큰 (`Board`) | `.token solved dead` — **정답 공개 토큰만** | 메모 토큰은 안 받는다 |

### `✕` 기호 충돌 — 보드에서는 공개 후에만 쓴다

보드에는 이미 `✕` 가 있다. `.mark-x` — 메모 브러시의 `✕ 빈칸`, 뜻은 **"여긴 아무도 없다"** 다.
피해자 X 의 뜻은 정반대에 가깝다. 같은 모양이 두 뜻을 가지면 눈이 먼저 헷갈린다 —
잔디 무늬와 `설 수 없음` 빗금이 겪은 것과 같은 형태다.

**시간이 둘을 가른다.** `Board.tsx` 가 `revealed` 로 메모와 정답 토큰을 배타적으로 나눈다.

```tsx
const mark   = revealed ? undefined : marks[k];         // 메모 — 공개 前에만
const person = revealed ? personAt.get(k) : undefined;  // 정답 토큰 — 공개 後에만
```

| | 공개 前 | 공개 後 |
|---|---|---|
| `.mark-x` `✕` (아무도 없다) | 있음 | **없음** — `marks` 가 통째로 가려진다 |
| 피해자 X | **없음** | 있음 |

그래서 규약은 이렇다.

> **보드의 빨간 X 는 `revealed` 화면에만 있다.** 메모 토큰(`.token` 단독)은 안 받는다.

메모 토큰에까지 얹으면 `.mark-x` 와 **같은 화면에 동시에** 놓인다 — 옆 칸엔 "아무도 없다"는
`✕`, 이 칸엔 X 그어진 `V` 다. 브러시→스탬프 대응(A 를 고르면 A 모양이 찍힌다)이 완충해 주긴
하지만, 공짜로 피할 수 있는 충돌을 감수할 이유가 없다.

**공개 화면이 더 말하는 것은 이미 이 보드의 방식이다.** `.token.solved.culprit` 이 범인에게만
따로 등장 모션을 주고, `.cell.crime` 이 범행 방에 테두리를 두른다. 피해자 X 도 같은 자리에
선다 — 규칙("피해자와 같은 방")을 결과 화면에서 눈으로 확인시킨다.

`board.test.ts` 가 이 배타성을 직접 검사한다. 나중에 누가 메모 토큰에 얹으면 거기서 걸린다.

## 2. 증언 목록의 V 행

행 구조는 그대로 두고 둘을 더한다.

- **뱃지에 빨간 X** (위 1번).
- **이름 뒤에 `피해자` 알약** (`.dead-tag`, `clues.css`). 모양은 범례 알약과 같지만 **색은
  다르다** — 범례의 분홍(`#f2dcd8`)·초록(`#dcefdd`)은 `설 수 없음`·`설 수 있음` 이라는
  **칸** 이야기에 묶인 색쌍이라, **사람** 이야기인 피해자가 거기 끼면 같은 분홍이 두 뜻을
  진다. 그래서 같은 줄 뱃지의 빨간 X 와 같은 `--accent` 로 묶는다(테두리·글자 빨강, 배경
  흰색 — `.chip.danger` 와 같은 언어). `flex: none` 이라 모바일에서 줄어드는 건 어차피 장식인
  증언 문구 쪽이다 — `mobile.css` 가 `.clue-text` 를 `nowrap` + 말줄임으로 잡아 뒀다.
  데스크톱은 `.dclues .clue-row` 가 `align-items: flex-start` 라 문구가 접히고 줄이 자란다.
- `aria-label` 을 `${name} (피해자) 로 표시하기` 로 바꾼다. 그림·글자·낭독이 같은 말을 한다.

`VICTIM_LINE` 은 **안 건드린다.** 브리핑 카드에서는 말풍선이라 1인칭이 맞고, 증언 줄에서는
이제 뱃지와 꼬리표가 사실을 말한다.

**V 행은 여전히 눌러야 하는 브러시다.** 피해자가 어디 있었는지도 추리해서 표시해야 한다 —
비활성처럼 보이게 만들면 안 된다. 흐리게 하거나 커서를 바꾸지 않는다.

## 3. 지목 패널의 한 줄

`AccusePanel` 에 `victim: Person` prop 을 더한다. `useGame` 이 이미 `victim` 을 내보낸다.
두 셸이 같은 컴포넌트를 쓰므로 여기 한 번 넣으면 데스크톱 사이드 열과 모바일 지목 시트가
같이 고쳐진다.

용의자 목록 **위**, `bare` 여부와 무관하게 늘 그린다.

```tsx
<p className="accuse-why">
  <span className="clue-badge dead" style={{ background: victim.color }} aria-hidden="true">V</span>
  피해자는 <b>{victim.name}</b>. 그와 같은 방에 있던 용의자가 범인이야.
</p>
```

- 문장 앞의 뱃지는 증언 목록의 그것과 **같은 컴포넌트 모양**이다. 문장 속 기호가 화면의
  기호와 같아야 이어진다. `aria-hidden` 이라 낭독은 문장만 읽는다.
- 조사(`와/과`)를 피하려고 `피해자는 {이름}.` 로 끊고 `그와` 로 받는다 — 이름 받침에
  상관없이 늘 맞는 문장이다. 앱에는 조사 헬퍼가 없다.
- 이 한 줄이 **V 가 용의자 목록에 없는 이유**까지 같이 답한다.

`panels.css` 의 `.accuse-why .clue-badge` 는 `display: inline-grid` 로만 바꾼다. 전역
클래스의 **기본 스타일을 부모 밑으로 옮기는 게 아니라** 문단 안에서의 배치만 맞추는 것이다
(`.footer .ver` 로 통째로 묶여 모바일에서 스타일이 빠졌던 것과는 다른 경우).

## 4. 모바일 첫 실행

### 키를 나눈다

`history.ts` 에 `seenBrief()` / `markBriefSeen()` 을 더한다. 키는 **`murdoku.brief`**,
기존 `murdoku.tour` 와 별개다.

한 키로 묶으면 **모바일로 먼저 본 사람이 데스크톱에서 스포트라이트 온보딩을 영영 못 본다.**
둘은 다른 물건이다 — 모바일 브리핑은 사건과 규칙을, 데스크톱 온보딩은 화면 구조를 가르친다.

반대 방향(데스크톱 사용자가 창을 760px 아래로 좁혀 브리핑이 한 번 열림)은 그 화면을 처음
보는 게 맞으니 오히려 옳다.

### 마운트 effect 로 연다

```tsx
useEffect(() => {
  if (seenBrief()) return;
  setSheet('case');
  setFirstBrief(true);
  markBriefSeen();
}, []);
```

`useState` 초기값으로 읽으면 서버 렌더에서도 열린 채 나간다 — `App.tsx` 의 온보딩과 같은
이유로 effect 다.

시트 안에는 **브리핑 → 인물 카드(빨간 X + `피해자`) → 범례 → 규칙 전문**이 이미 다 있다.
새 문구를 만들지 않는다.

### 돌아오는 길을 알려준다

저절로 열린 시트는 *어디서 왔는지*를 안 알려준다. 닫고 나면 규칙에 다시 닿는 길을 모른다.

**첫 실행으로 열렸을 때만** 시트 맨 위에 한 줄을 붙인다 (`.brief-again`, `case.css`).

> 위쪽 **사건 제목**을 누르면 이 브리핑을 언제든 다시 볼 수 있어.

`close()` 가 `firstBrief` 를 끄므로 제목 버튼으로 다시 열면 안 나온다. 데스크톱 온보딩
마지막 단계가 "이 안내는 증언 목록 아래 ? 로 다시 볼 수 있다"고 말하는 것과 같은 정신이다.

맨 위에 둔다 — 맨 아래에 두면 시트를 끝까지 내리지 않는 사람은 못 본다.

| `board.test.ts` | 정답 공개 화면에서 **피해자 토큰만** `dead` 다. 그리고 **메모 화면에는 `dead` 가 하나도 없다** — `.mark-x` 와 같은 화면에 두 뜻의 X 가 놓이지 않는다 |
| `repo.test.ts` | `--dead-x` 가 `base.css` 에 한 번만 정의되고, `clues.css`·`board.css` 는 값이 아니라 `var(--dead-x)` 를 참조한다 |
| `history.test.ts` | `markBriefSeen()` 이 `seenTour()` 를 참으로 만들지 않는다 |

마지막 것이 이 작업의 핵심 자산이다. **키를 합치면 데스크톱 온보딩이 조용히 죽는데
화면으로는 안 보인다.** 테스트 환경에 jsdom 이 없지만 `readLS`/`writeLS` 가 `try/catch` 라
`globalThis.localStorage` 에 Map 기반 가짜를 끼우면 그대로 돈다.

첫 실행 자동 열기 자체는 마운트 effect 라 `renderToStaticMarkup` 에 안 나온다 — 시트 내용과
키 분리를 각각 지키는 것으로 대신한다.

CSS 원문을 읽는 검사는 `vite.config.ts` 의 `test: { css: true }` 에 기대고 있다
(`repo.test.ts` 가 이미 그 구멍을 막고 있다).

## 형제 세션과 겹치는 곳

`copilot/cautious-tribble` 의 `2026-08-04-rules-clarity-design.md` 가 같은 피드백 묶음의
다른 두 건(사선 빗금 예약 · `옆 = 상하좌우`)을 설계해 뒀다.

| 파일 | 상태 |
|---|---|
| `src/styles/base.css` `:root` | **충돌** — 그쪽 `--nostand`, 이쪽 `--dead-x`. 같은 블록 |
| `CHANGELOG.md` · `package.json` | **확실히 충돌** — 먼저 끝나는 쪽이 바닥, 나중이 rebase |
| `GamePanels.tsx` | 그쪽 `RulesPanel`·`LegendPanel` / 이쪽 `AccusePanel` — 다른 함수 |
| `panels.css` · `repo.test.ts` · `render.test.ts` | 다른 블록 · 다른 `describe` |
| `src/data/tour.ts` | **그쪽만** 건드린다. 이쪽은 안 건드린다 |

그쪽 각도 검사가 `board.css` 에서 `src/styles/` 전체로 넓어진다 — 사선
`repeating-linear-gradient` 는 `--nostand` 선언 하나만 허용한다. `--dead-x` 는 각도 있는
`linear-gradient` 두 겹이지만 **반복(`repeating-`)이 아니라서** 걸리지 않는다.

두 작업 다 "규칙이 스스로 설명하게 한다"는 같은 방향이고, 기호를 뜻 하나에 예약한다는
원칙도 같다 — 사선 빗금은 `설 수 없음`, 빨간 X 는 `피해자`.

### 검토에서 바뀐 것

첫 설계는 보드의 **메모 토큰에도** X 를 얹었다. 형제 세션이 `.mark-x` 와의 충돌을 지적했고,
확인해보니 메모 토큰은 `.mark-x` 와 **같은 공개 前 화면**이라 둘이 동시에 뜬다. 그래서
보드에서는 공개 後 토큰만 X 를 받는 것으로 좁혔다 (위 1번).
