# 사건 테마 `사무실` 추가

## 문제

테마가 `저택`·`농장` 둘뿐이라 시드를 아무리 바꿔도 사건의 배경이 두 종류로 돌아온다.
방 이름·가구·직업·제목이 테마 단위로 묶여 있으므로, 세 번째 테마를 넣으면
같은 규칙 그대로 사건의 결이 하나 더 늘어난다.

현대 IT 회사의 한 층을 배경으로 하는 `사무실` 테마를 `THEMES` 에 추가한다.

## 접근

`src/data/content.ts` 의 `THEMES` 배열에 `OFFICE` 상수를 하나 더 넣는 것이 작업의 중심이다.
테마는 이미 방·가구·벽부착물·안뜰·제목·브리핑·직업을 한 묶음으로 들고 있고,
생성기·솔버·렌더러는 전부 `Theme` 를 인자로 받아 동작하므로 게임 로직은 손대지 않는다.

테마 데이터 밖으로 번지는 변경은 두 가지뿐이다.

- **바닥 재질 2종 추가** — `FloorKind` 에 `coated`·`acrylic` 을 넣고 `board.css` 에 질감을 그린다.
- **가구 아이콘 6종 추가** — `sprite.svg` 에 사무실 고유 물건을 그린다.

## 방 · 바닥

방 이름은 9개(평면도가 최대 9개 방까지 나온다). 바닥은 4종.

| 방 | 바닥 | `FloorKind` |
|---|---|---|
| A존 · B존 · 라운지 | 마루 | `wood` (기존) |
| 복도 · 창고 | 코팅바닥 | `coated` (신규) |
| 화장실 · 기계실 | 타일 | `tile` (기존) |
| 엘리베이터 · 회의실 | 아크릴바닥 | `acrylic` (신규) |

신규 바닥의 질감은 기존 것과 같은 방식으로 `--floor-tint` + `--floor-img` 로 그린다.

- `coated` — 광택 있는 밝은 회색에 넓은 사선 반사. 반사를 한 방향으로 흘려야 무늬가 아니라
  빛으로 읽힌다.
- `acrylic` — 서늘한 반투명 톤에 격자 이음매. 면은 비어 있고 이음매만 보여야 유리처럼 보인다.

무늬는 전부 옅게 깐다. 칸선보다 세면 칸을 셀 수 없게 된다.

`OUTDOOR_FLOORS`(잔디·흙)는 그대로 둔다. 사무실은 전부 실내라 `outdoorItems` 를 두지 않고
벽부착물은 창문·문만 쓴다.

안뜰(도넛 실루엣일 때 건물 안쪽에 갇히는 빈 칸)은 `아트리움` 🪴 / 잔디 바닥.
저택은 안뜰 ⛲, 농장은 연못 💧 이었다.

14종. 그중 6종만 새로 그리고 나머지는 같은 물건이라 기존 스프라이트를 재사용한다.

지켜야 하는 제약 세 가지.

1. **9개 방 전부 전용 가구 후보가 1개 이상.** `placeFurniture` 는 어느 방이든 가구를 하나도
   못 넣으면 `null` 을 돌려 평면도를 다시 뽑는다. 가장 빠듯한 방은 엘리베이터(전용 1개 +
   범용 3개)라 방 정렬에서 가장 먼저 채워진다.
2. **재사용하는 `kind` 는 `size` 를 바꾸지 않는다.** 스프라이트의 viewBox 가 한 칸당 24
   기준으로 고정되어 있고 `repo.test.ts` 가 `kind` → viewBox 일치를 검사한다.
3. **한 칸짜리 가구가 충분해야 한다.** 방은 2칸까지 작아질 수 있고 그때 `budget` 은 1이라
   막는 가구는 1칸짜리만 들어간다. 사무실은 복사기·정수기·모니터·화분·양동이 5종으로
   저택(5종)·농장(5종)과 같은 수준이다.

신규 스프라이트 6종은 기존 디자인 언어를 그대로 따른다 — 두꺼운 잉크 선 + 플랫 색,
선 색·굵기는 지정하지 않고 `svg.art` 에서 상속(`fill: none; stroke: currentColor;
stroke-width: 1.6`), `id="i-<kind>"`, 한 칸당 viewBox 24(2칸이면 48×24).
두 칸짜리는 칸 경계(x=24)에 부품 경계를 맞춰 칸마다 제 몫이 보이게 그린다.

## 문구

- **직업 10** — 팀장 · 개발자 · 디자이너 · 기획자 · 인턴 · 경비원 · 미화원 · 인사담당자 ·
  영업사원 · 외주 개발자
- **제목 10** — 야근하던 밤 · 출입카드는 한 장뿐 · 꺼지지 않은 모니터 · 서버실의 경고음 ·
  삭제된 커밋 · 엘리베이터는 12층에서 멈췄다 · 식어버린 아메리카노 · 금요일 여섯 시의 회의 ·
  화이트보드에 남은 글씨 · 정전된 3분
- **브리핑 5** — 출입 기록 · 기계실 카드키 · 꺼진 모니터를 소재로. 마지막 한 줄은 기존 테마와
  같은 형식(`피해자와 마지막까지 같은 방에 있던 사람을 찾아라.`)을 유지한다.

증언 문구는 `clueText` 가 조사 없이 `에`·`에서`·`옆에` 만 붙이므로 방 이름·가구 이름의
받침을 신경 쓸 필요가 없다.

## 검증

기존 테스트가 `THEMES` 를 순회하므로 새 테스트는 만들지 않는다. 새 테마는 자동으로 검사망에 걸린다.

| 테스트 | 새 테마에 대해 무엇을 보장하나 |
|---|---|
| `floorplan.test.ts` | 마스크마다 행·열 완전 매칭이 존재하고 방이 끊기지 않는다 |
| `generate.test.ts` | 난이도 4·5·6·7 × 60시드가 전부 생성되고, 세 테마가 빠짐없이 등장한다 |
| `repo.test.ts` | 재사용·신규 `kind` 의 스프라이트 viewBox 가 `size` 와 맞는다 |
| `render.test.ts` | 칸마다 바닥 재질이 붙는다 (테마 무관) |

**진짜 관문은 `generate.test.ts` 의 스윕이다.** `generatePuzzle` 은 실패해도 조용히
300×20×60 회 되던지므로, 방 하나가 가구를 못 받는 구성이면 에러 없이 재시도만 하다가
맨 끝에서 throw 한다. 스윕이 통과하고 `seen` 에 `office` 가 들어가야 완료다.

새 불변식은 하나만 늘린다 — **바닥 재질마다 CSS 가 있다.** 지금 `FloorKind` 는 타입
별칭이라 실행 시점에 순회할 수 없어서, 재질을 넣고 질감을 빠뜨려도 그 방이 조용히
기본 타일색으로 깔릴 뿐 아무도 모른다. 값 목록(`FLOOR_KINDS`)으로 바꿔 그 구멍을 막는다.

## 문서 · 릴리스

- `README.md` 의 테마 표에 `사무실` 행 추가.
- `CHANGELOG.md` 맨 위에 새 버전 항목을 쓰고 `npm version patch`.

## 하지 않는 것

- 게임 규칙·솔버·생성기 로직 변경 없음. 테마는 데이터일 뿐이다.
- 방 이름을 10개 이상으로 늘리지 않는다. `MAX_ROOMS` 가 9라 더 넣어도 쓰이지 않는다.
- 테마별 UI 분기 없음. 상단바의 `theme.label` 이 이미 테마를 표시한다.
- 스프라이트가 없는 가구를 금지하지 않는다. 이모지 폴백은 의도된 설계이고
  `repo.test.ts` 가 일부러 건너뛴다.
