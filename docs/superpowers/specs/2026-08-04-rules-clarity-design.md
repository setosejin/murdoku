# 규칙이 스스로 설명하게 하기 — 빗금의 뜻과 '옆'의 범위

## 문제

플레이한 사람이 두 가지를 지적했다. 둘 다 규칙 자체가 아니라 **규칙을 전하는 방식**의
문제다. 퍼즐의 정답은 지금도 맞게 나온다.

### 1. 빗금이 두 가지 뜻으로 쓰인다

`설 수 없는 칸` 표시와 `잔디 바닥` 무늬가 **각도까지 같다**.

| 자리 | 값 | 각도 |
|---|---|---|
| `.cell.blocked::before` (설 수 없음) | `repeating-linear-gradient(45deg, #0000 0 6px, #23201c12 6px 8px)` | 45° |
| `.cell[data-floor='grass']` (잔디) | `repeating-linear-gradient(45deg, #0000 0 4px, #2d6a3f1f 4px 5px)` | 45° |

게다가 잔디 쪽이 더 진하다 — `#1f`(12%) 대 `#12`(7%). **뜻을 가진 기호가 배경 질감보다
옅다.** `straw`(-30°)·`water`(20°)·`coated`(115°)도 같은 사선 계열이라 사선이라는
모양 하나가 네 가지 다른 것을 가리키고 있다.

말로 설명해서 풀 수 있는 문제가 아니다. 두 그림이 같으면 눈이 먼저 헷갈린다.

### 2. '옆'이 대각선을 포함하는지 앱 어디에도 안 적혀 있다

엔진은 상하좌우 4방향이다 (`clues.ts` 의 `DIRS`). 그런데 화면의 말은 이렇다.

| 자리 | 지금 문구 |
|---|---|
| 규칙 패널 4 | `'옆'은 같은 방에서 인접해 있다는 뜻` |
| 규칙 패널 5 | `'~에서 나왔다'는 그 방과 벽을 맞댄, 그 방이 아닌 칸` |
| 온보딩 2단계 | `…같은 방 안에서 붙어 있다는 뜻이라 방 경계를 넘지 않는다` |

`상하좌우` 라는 말은 `README.md` 에만 있다. 플레이어는 README 를 안 읽는다.
`인접`·`붙어 있다` 는 대각선을 배제하지 않는 말이라, 대각선을 세면 후보 칸이 두 배가 되고
퍼즐이 안 풀린다.

## 접근

세 갈래로 나눠 고친다.

1. **사선 빗금을 `설 수 없음` 전용 기호로 예약한다** — 바닥 재질에서 사선을 걷어낸다.
2. **`옆 = 상하좌우` 를 그림으로 말한다** — 규칙 패널에 3×3 다이어그램, 문구 세 곳 교정.
3. **범례가 보드의 축소판이 된다** — 범례 줄에 같은 빗금을 깔아 기호와 뜻을 잇는다.

게임 로직(`clues.ts`·`solve.ts`·`generate.ts`)은 손대지 않는다. 규칙은 원래 상하좌우였고
말과 그림이 그걸 못 따라가고 있었을 뿐이다. **같은 시드는 같은 답을 유지한다.**

## 1. 사선 빗금 예약

### 규약

> `board.css` 의 바닥 질감(`--floor-img`)에서 `repeating-linear-gradient` 는
> `0deg`/`90deg` 만 쓴다. **사선으로 반복되는 선은 `설 수 없음` 하나만 갖는다.**

### 바닥 재질 교체

| 재질 | 지금 | 바꾼 뒤 | 왜 |
|---|---|---|---|
| `grass` 잔디 | `45deg` 가는 사선 | 짧은 **세로 풀잎** 점묘 (`radial-gradient` 로 1×3px 타원, 7×9px 타일) | 빗금과 정면 충돌. 풀잎은 원래 세로로 선다 |
| `straw` 짚 | `-30deg` 가는 사선 | **가로·세로 짧은 토막** 두 겹 (썰린 짚) | 사선 제거. `soil` 의 동그란 점과도 갈린다 |
| `water` 물 | `20deg` 사선 | `repeating-radial-gradient` **동심 물결** | 잔물결은 원래 동심원이다 |
| `coated` 코팅 | `115deg` 넓은 광택 | **`90deg` 세로 광택** (각도만 바꾼다) | 천장 조명 반사로 읽혀 오히려 더 사무실답다 |

바꾸지 않는 것 — `wood`(0° 결)·`tile`(체크)·`carpet`(점)·`soil`(점)·`acrylic`(0°+90° 이음매).

무늬는 전부 지금처럼 옅게 둔다. 칸선보다 세면 칸을 셀 수 없게 된다.

`water` 의 동심원이 물결이 아니라 물방울무늬로 읽히면 `0deg` 가로 물결선으로 내린다.
브라우저에서 실물을 보고 판단한다.

### 빗금 자체는 진해진다

`#23201c12`(7%) → `#23201c26`(15%), 간격 `6px·2px` → `5px·2px`.
바닥 질감(최대 12%)보다 확실히 위에 서야 "이건 무늬가 아니라 표시" 로 읽힌다.

값은 `base.css` 의 `:root` 에 **한 번만** 둔다.

```css
--nostand: repeating-linear-gradient(45deg, #0000 0 5px, #23201c26 5px 7px);
```

`board.css` 의 `.cell.blocked::before` 와 `panels.css` 의 범례가 이걸 참조한다.
값이 두 벌이면 언젠가 갈라진다.

Safari 의 `var()` 캐싱 함정(webkit#202259)은 값이 바뀌는 `repeat()`·`calc()` 안쪽에서
나는 것이다. `--nostand` 는 루트에 고정된 상수라 해당하지 않는다.

### 따져보고 버린 대안

- **교차 빗금(45°+135°)으로만 바꾸기** — 바닥을 안 건드려도 되지만 칸이 시끄러워지고,
  "사선 = 못 섬" 이라는 단일 시각 언어가 안 생긴다. 새 테마가 또 사선 바닥을 깔면 원점이다.
- **모서리에 🚫 배지** — 가구 그림·이름표와 자리를 다투고 7×7 에서는 안 보인다.
- **글로만 설명하기** — 두 그림이 같은 한 눈이 먼저 헷갈린다. 지적의 원인을 안 없앤다.

## 2. `옆 = 상하좌우` 다이어그램

`GamePanels.tsx` 의 `RulesPanel` 안, 규칙 4번 아래에 66px 남짓한 격자를 놓는다.

```
✕  ✓  ✕
✓  ■  ✓      ■ = 가구·창문 같은 대상
✕  ✓  ✕
```

- ✓ 칸은 초록(`설 수 있음` 알약과 같은 `#dcefdd`), ✕ 칸은 흐리게, 가운데는 잉크색.
- **대각선 칸에 빗금을 쓰지 않는다.** 1번에서 예약한 뜻과 섞이면 안 된다.
- 격자는 **맨해튼 거리로 만든다** — `|dr| + |dc| === 1` 이면 ✓. 엔진의 `DIRS` 와 같은
  규칙에서 나온 그림이라 손으로 찍은 표가 아니다.
- `aria-hidden="true"`. 옆 문장이 혼자서도 뜻이 통한다.

캡션은 규칙 문장이 겸한다. 다이어그램은 **하나만** 둔다 — 규칙 5번까지 그리면 패널이 표가 된다.

### 문구 교정

| 자리 | 바꾼 뒤 |
|---|---|
| 규칙 패널 4 | `'옆'은 같은 방 안에서 상하좌우로 붙은 칸 — 대각선은 아니다` |
| 규칙 패널 5 | `'~에서 나왔다'는 그 방과 상하좌우로 벽을 맞댄, 그 방이 아닌 칸` |
| 온보딩 2단계 (`data/tour.ts`) | `…'옆'은 같은 방 안에서 상하좌우로 붙어 있다는 뜻이다. 대각선은 아니고, 방 경계도 넘지 않는다.` |

규칙 5(`FROM_ROOM`)도 같은 4방향인데 앱 어디에도 안 적혀 있었다. 4번과 달리 **방 경계를
넘는다**는 대비가 살아 있어야 하므로 그 부분은 그대로 둔다.

## 3. 범례가 보드의 축소판이 된다

지금 범례는 `설 수 있음` / `설 수 없음` 을 **글자로만** 말한다. 보드는 **빗금으로** 말한다.
둘을 잇는 고리가 없다.

`LegendPanel` 의 가구 그림을 칸 모양 껍데기(`.legend-tile`)로 감싸고, `설 수 없음` 줄에만
`var(--nostand)` 를 깐다. 보드에서 빗금이 가구 **아래** 깔리는 것과 같은 순서다.

```
[🪑  ← 빗금 바닥 위]   탁자    (설 수 없음)
[🛏️  ← 맨 바닥 위]    침대    (설 수 있음)
```

범례 줄이 보드 칸의 축소판이 되므로 "이 무늬 = 못 선다" 가 한 번에 잎힌다.

마크업은 `<Art>` 를 `<span className="legend-tile">` 로 감싸는 한 겹뿐이다.
`.legend li` 의 첫 열(38px)은 그대로 쓴다.
