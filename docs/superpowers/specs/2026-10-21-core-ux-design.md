# 핵심 플레이 UX와 화면 가리기

작성일: 2026-10-21

## 목표와 승인 범위

현재의 한 화면·보드 우선 레이아웃은 유지한다. 플레이어가 실수로 진행을 잃거나,
끝난 사건의 결과가 바뀌거나, 조작법을 찾느라 막히는 문제를 먼저 고친다.

사용자는 다음 범위를 선택했다.

- 핵심 UX 개선: 진행 보호·완료 상태·규칙/조작 안내·접근성.
- 진행 중 사건은 이 기기에 하나만 저장하고 복원한다.
- 실제로 진행을 버리는 동작만 확인한다.
- 추가 요청: 회사 등에서 필요할 때 버튼으로 게임 화면을 잠시 가린다.
- 가리기 방식: **전체 화면을 강하게 흐리고 `계속하기` 버튼만 표시**한다.
  메모를 유지하고, 열린 사건·규칙·메뉴도 가리며, 뒤쪽 게임 조작은 막는다.

전면적인 메뉴·계정 개편, 여러 사건 동시 저장, 서버 진행 동기화,
무제한 실행 취소는 이번 범위가 아니다. 이번 작업은 검토와 계획이며 앱 구현은 하지 않는다.

## 검토 기준

- 기준: `origin/main`의 `f07c8a3921246a7aa0f65c76cd2115e97c784b03`.
- 이 커밋의 앱 버전은 v0.13.3이다. 현재 작업 브랜치의 과거 화면이 아니라
  최신 main을 별도 사본으로 실행했다.
- 기존 UI 검사: `mobile.test.ts`, `render.test.ts`, `board.test.ts`의 74개 통과.
- WebKit·Chromium에서 화면 6종 × 난이도 `4 → 6 → 7 → 4`, 총 48회 측정.
  화면은 `360×560`, `375×667`, `393×852`, `844×390`, `900×700`, `1280×800`.
  레이아웃 측정 시드는 `ux-audit-20261021`로 고정했다.
- 이 범위에서는 페이지·보드 잘림이 없었다. 보드 크기 재설계는 하지 않는다.
- 실물 iPhone Safari·VoiceOver·TalkBack은 확인하지 않았다.
  계정 서버가 없는 로컬 빌드를 사용했으므로 실제 계정·동기화 품질도 판정하지 않는다.

피해자 표식, 승리 조건 문장, 빗금과 바닥 재질 구분, 인접 방향 그림은 이미 반영되어 있다.
이를 새 개선 과제로 다시 잡지 않는다.

## 1. 진행 보호

### 현재 사건 하나를 기기에 저장

저장 대상은 `n`, `seed`, 메모, 선택한 브러시, 지목 후보, 시도 횟수,
판정 결과, 정답 공개·포기 여부, 획득 점수다. 퍼즐 전체나 정답 배치는 저장하지 않는다.
복원 시 기존 `generatePuzzle(n, seed)`를 사용한다.

- 유효한 저장본이 있으면 새 사건을 먼저 만들지 않고 바로 복원한다.
- 저장 초기화와 첫 저장 효과가 경합하여 기존 저장본을 덮어쓰면 안 된다.
- 진행 중·해결·포기 상태를 함께 저장한다. 새로고침으로 시도 횟수나 포기가 초기화되면 안 된다.
- 완료 상태 복원이 완료 기록을 다시 추가하지 않게 한다.
- 선택한 난이도는 같은 사건의 일부로 유지한다.
- 저장 형식 식별자를 둔다. 생성 결과의 의미가 바뀌는 변경 때 호환성을 함께 검토한다.
- 저장본은 신뢰하지 않는다. 난이도·시드 길이·좌표·인물 ID·상태 조합을 검사한다.
- 손상·미지원 저장본과 저장 공간 접근 실패를 구분해 사용자에게 알린다.
  저장하지 못했는데 `저장됨`으로 표시하지 않는다.

`history.ts`의 완료 기록과 현재 사건 저장을 분리한다.
계정·순위 서버와 현재 사건 저장을 연결하지 않는다.

### 실수로 버리지 않기

- **현재 난이도 재선택은 아무 변화가 없다.** `DifficultySeg`에서 막는다.
  `reset()`에서 같은 난이도를 모두 막으면 정상적인 `새 사건`까지 막히므로 그렇게 하지 않는다.
- 새 사건·다른 난이도·시드·기록 열기는 공통 사건 전환 경로를 사용한다.
- 진행 중이며 메모 또는 지목 시도가 있을 때만 진행을 버릴지 확인한다.
  빈 새 판이나 이미 끝난 판에는 확인을 요구하지 않는다.
- 전체 메모 삭제는 메모가 있을 때만 확인한다. 취소하면 브러시와 메모도 유지한다.
- 첫 구현은 브라우저 기본 확인창을 사용한다. 별도 확인 모달 체계를 만들지 않는다.
- 전환 성공 여부를 호출자에게 돌려준다. 성공한 시드·기록 열기는 시트를 닫고 보드를 보여주며,
  취소 시에는 입력과 현재 시트를 유지한다.
- 손님 메뉴를 포함해 기존 `reset`·`clearMarks` 호출 경로를 모두 연결한다.

## 2. 끝난 사건의 결과 고정

- 해결·포기 후에는 `useGame`의 공통 지목 함수가 추가 지목을 거부한다.
  버튼만 비활성화해 다른 호출 경로가 남게 하지 않는다.
- 해결 뒤 후보 변경으로 결과·시도 횟수·획득 점수가 바뀌지 않는다.
- 정답 공개 중에는 뒤에 숨은 메모를 변경하지 않는다.
- 기존 지목 주 버튼 자리를 `다음 사건`으로 바꾼다. 새 행을 만들지 않는다.
- 정답 보기/숨기기는 계속 가능하지만 해결·포기 상태를 되돌리지 않는다.
- 이미 완료한 사건을 기록에서 다시 풀면 재플레이임과 추가 점수가 없음을 알린다.
  최초 해결 점수만 합산하는 기존 정책은 유지한다.
- 완료 기록은 사건 처리 한 번에 한 번만 추가한다. 빠른 연속 입력도 검증한다.

## 3. 규칙과 첫 조작 안내

기존 `copilot/add-rules-button`의 설계 커밋 `837f3f7`을 재사용한다.
이 브랜치에는 설계 문서만 있고 구현은 없다. 당시의 릴리스 번호·행 번호는 재사용하지 않는다.

- `게임 방법` 시트 하나에 짧은 조작 안내 → 규칙 → 이번 사건의 가구 범례를 둔다.
- 안내는 `증언을 눌러 인물 선택 → 보드 칸을 눌러 메모 → 같은 표시를 다시 누르면 지우기`.
  `✕ 빈칸`의 뜻과 피해자와 같은 방의 용의자를 지목한다는 목표도 설명한다.
- `RulesPanel`·`LegendPanel`을 재사용한다. 규칙 판정과 퍼즐 생성은 바꾸지 않는다.
- 사건 브리핑은 사건 설명·인물 카드에 집중한다.
- 데스크톱의 기존 `?`는 게임 방법을 열고, 화면 안내 투어는 그 안에서 다시 연다.
- 모바일은 상단바에 같은 이름의 `?`를 둔다. 새로 방문한 모바일 사용자는
  긴 인물 카드 대신 조작법이 먼저 나오는 게임 방법을 본다.
- 기존 방문 여부 표식을 존중해 업데이트마다 안내를 강제하지 않는다.
- 손님 메뉴 도움말·투어 문구·README도 같은 진입 경로를 가리키게 한다.
- 시트에서 투어로 넘어갈 때 두 모달이 포커스를 빼앗지 않는지 실제로 확인한다.

## 4. 빠른 화면 가리기

### 사용 동작

- 기본 화면 상단에 `화면 가리기` 버튼을 둔다. 메뉴 안으로 숨기지 않는다.
- 누르면 **게임 이름·보드·증언·결과·열린 모달까지 강한 블러**로 덮고,
  전면에는 `계속하기` 버튼만 표시한다.
- `계속하기` 또는 Escape로 돌아간다. 가림 영역 바깥을 잘못 눌러 해제되지 않는다.
- 가리는 동안 게임의 클릭·탭·키보드 조작을 막는다. 화면 읽기 기능도 뒤쪽 게임에 접근하지 않는다.
- 복귀하면 같은 사건·메모·시도 횟수와 원래 포커스로 돌아간다.
  화면 회전으로 원래 버튼이 사라졌다면 현재 셸의 가리기 버튼으로 포커스를 돌린다.
- 가리기는 일시적 UI 상태다. 인증·로그아웃·사건 포기·점수 변경을 하지 않는다.
  새로고침 이후 가림 유지나 창 이탈 시 자동 가리기는 이번 범위가 아니다.

### 구현 방향

- 게임 상태와 별개로 `App` 수준에서 가림 상태를 한 번만 소유한다.
- 네이티브 모달 `<dialog>`와 그 `::backdrop`의 블러를 사용한다.
  앱 컨테이너에 `filter`만 주면 브라우저의 최상위 레이어에 뜬 모달을 놓칠 수 있다.
- 가림 레이어는 모바일·데스크톱 셸 교체와 관계없이 유지한다.
  가리는 도중 회전·리사이즈·초기 안내 효과로 다른 모달이 그 위에 올라오면 안 된다.
- `Sheet` 공통 헤더에서도 가릴 수 있게 한다. 별도의 네이티브 dialog를 쓰는
  투어·피드백·버전 기록·손님 메뉴에도 같은 가리기 동작을 연결한다.
- 새로 생성한 스크린샷으로 가리는 방식은 쓰지 않는다. 의존성도 추가하지 않는다.
- 블러를 지원하지 않는 환경은 불투명한 중립 배경으로 덮는다.
- 가리기 진입에는 지연 애니메이션을 넣지 않는다.

**한계:** 블러는 옆사람에게 화면 내용을 덜 보이게 하는 편의 기능이다.
탭 제목·아이콘·운영체제 미리보기·개발자 도구까지 숨기는 보안 기능은 아니다.

**구현 검증 메모 (2026-10-26):** WebKit은 `dialog::backdrop`의 블러 값을 계산하고도
실제 픽셀에는 적용하지 않았다. 따라서 입력 차단은 네이티브 가림 dialog로 유지하고,
배경 셸과 열린 dialog에 각각 `filter: blur(24px)`를 적용한다.
규칙 화면을 띄운 상태에서도 글자가 흐려지는지 픽셀 검사로 재현·확인한다.

### 공간 제약

`?`와 가리기 버튼을 함께 추가해도 상단바를 두 줄로 만들지 않는다.
게임 이름과 조작 버튼의 터치 영역은 유지한다. 좁은 폭에서는 사건 제목을 먼저 줄이고,
필요하면 상단의 테마 꼬리표를 생략한다. 전체 제목·테마는 브리핑에서 확인할 수 있다.
보드 높이를 줄이거나 터치 버튼을 작게 만들어 해결하지 않는다.

## 5. 읽어주는 정보와 화면의 일치

- 증언 버튼은 인물 이름·선택 상태뿐 아니라 실제 증언도 연결해 읽어준다.
- 보드 칸의 접근성 이름은 행·열·방·가구와 **현재 보이는** 메모 또는 공개된 인물을 말한다.
- 공개 화면에서는 피해자·범인도 구분한다. 공개 전에는 정답을 접근성 정보로 누설하지 않는다.
- 기본 버튼·네이티브 dialog의 키보드 동작을 유지한다. 새 격자 키보드 체계는 만들지 않는다.
- 가림·복귀·시트 전환 시 포커스가 사라지거나 뒤쪽 화면에 남지 않게 한다.

## 완료 기준

1. 새로고침 후 사건·난이도·메모·시도 횟수·포기 여부가 보존된다.
2. 현재 난이도를 다시 눌러도 시드와 메모가 변하지 않는다.
3. 모든 사건 전환 경로에서 확인 취소 시 아무 진행도 잃지 않는다.
4. 해결 후 재지목·후보 변경·연속 입력으로 결과나 점수가 변하지 않는다.
5. 양쪽 셸에서 한 번에 게임 방법을 열고, 첫 화면에서 메모 조작법을 읽을 수 있다.
6. 기본 화면과 열린 모달에서 즉시 가리고, 뒤쪽을 조작하지 못하며, 같은 상태로 복귀한다.
7. 기존 측정 화면과 `320×568`의 좁은 화면에서 새 버튼이 겹치지 않는다.
8. 기존 48회 측정과 같은 조건에서 보드·페이지 잘림이 없고 보드 크기가 줄지 않는다.
9. WebKit·Chromium의 실제 상호작용 확인, 관련 Vitest, lint, build가 통과한다.
   실물 iOS와 화면 읽기 기능 확인은 별도 수동 인수 항목으로 남긴다.

## 우선순위

1. 결과 고정·현재 난이도 재선택·진행 파기 확인·시드 열기 후 복귀.
2. 현재 사건 자동 저장·복원.
3. 규칙/조작 안내와 화면 가리기 버튼을 같은 상단바 기준으로 반영.
4. 접근성 이름·모달 포커스·화면 크기 회귀 확인.

계정·순위 메뉴 재배치, 공유 링크, 자동 힌트, 퍼즐 규칙 변경,
진행 중 사건의 기기 간 동기화, 여러 판 보관, 새 애니메이션은 보류한다.
